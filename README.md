# RoadChron-Data

Static signed price dataset for RoadChron. This is not a live API or a proxy. No driver, game, device or location data is collected by the collector. See the RoadChron source package setup guide before publishing. The workflow uses read-only repository permissions and a separate Pages deployment job; it cannot push source changes. Only the repository owner should have write access. It runs weekly on Friday at 04:17 UTC (GitHub may delay scheduled jobs), and manually via workflow_dispatch. Only enable it once the owner accepts the documented source reuse terms and GitHub hosting terms.

`public/fuel-prices.json` is an envelope containing a base64-encoded UTF-8 JSON payload and a P-256 ECDSA SHA-256 signature (64-byte IEEE P1363). All timestamps are UTC except local publication dates supplied by the price providers. Sources are the approved EIA, EU EnergyPrices, UK DESNZ, Statistics Norway, MITECO, PretCarburant.ro (Romania only) and ECB feeds; see public/SOURCES.md. DEF direct observations remain empty until an approved source is available. The client computes the labelled RoadChron DEF estimate using the existing signed EIA diesel feed. The client also computes a labelled AdBlue index from available AdBlue anchors. VATservice adapter is off by default; set ROADCHRON_VATSERVICE_APPROVED=true only after obtaining rights from relevant rights holders. Regional fuel estimates carry per-grade Estimated flags; source URLs are metadata, not instructions to fetch. Direct prices and estimates remain separate. An unavailable source is not marked fresh merely because the overall dataset was republished. The RoadChron client checks this static dataset every 24 hours, with an optional manual refresh and a one-minute manual cooldown. Romania is queried only on the first attempt of the weekly scheduled run; manual runs never use its weekly free quota. A failed or empty sample does not create a price. Update clients before publishing the new MITECO endpoint: older versions reject an unfamiliar source in the signed envelope. A previous signed dataset is loaded from the configured Pages endpoint; the first publication may return HTTP 404. The workflow leaves the previous deployment intact if collection fails. No private signing key may be committed.

Owner setup: Settings > Pages > Source: GitHub Actions. Under Settings > Secrets and variables > Actions, create repository secret `ROADCHRON_PRICE_SIGNING_KEY` (private PEM) and variable `ROADCHRON_PUBLISH_ENABLED` with value `true` only when ready. Run the workflow from the default branch. Enable 2FA and do not invite write collaborators or install apps with unnecessary write permissions. Public visitors may read or fork, but cannot change this repository. Review and pin third-party workflow action versions before production. The public configuration contains only the URL and public verification key. Keep an offline backup of the private key outside the repository. If the signing key is compromised, disable the workflow, rotate the key and release a newly configured RoadChron build; do not trust an old key.


## Validation and refresh

The scheduled run collects once per week. A manual run passes `--force` for approved unmetered feeds. The Romanian station endpoint is attempted only on the first run of a weekly schedule and only when a RON rate is available; there is no retry. Keep the original signing key, HTTP endpoint and GitHub secrets.
Run `dotnet restore tools/central-data/Collector.csproj --locked-mode` and `dotnet run -c Release --project tools/central-data/Collector.csproj -- selftest` to verify policies locally. `check-inputs DIRECTORY YYYY-MM-DD` validates already downloaded official inputs and a previously signed production envelope with the pinned public key.

If collection is partial, the signed envelope carries the latest provider statuses and retains still-valid earlier observations under their original observation dates. If all providers fail, collection exits with an error and Pages keeps its previous publication.
